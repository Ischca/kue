# Expo

## ExpoのCLIセットアップ

CLIによる自動検出、依存関係の追加、JSXの編集、録画のビルド設定はExpo専用です。ネイティブ、Flutter、Expoを使わないReact Nativeでは、各SDKの手順に従って直接導入してください。

### 実行手順

アプリの変更を保存してから、Expoアプリのパッケージまたはワークスペースのルートで次のコマンドを実行します。

```sh
npx kue-qa@0.6.0 init
```

現在のパッケージに `expo` の依存関係があれば、CLIはそのパッケージを使用します。それ以外の場合は `pnpm-workspace.yaml` の `packages`、または `package.json` の `workspaces` からExpoアプリを検出します。両方ある場合はpnpmの定義を優先します。

候補が1つなら自動で選択し、複数なら候補を表示して変更せずに終了します。対象を選ぶ場合は次のように指定します。

```sh
npx kue-qa@0.6.0 init --app apps/mobile
```

自動で探すのは、コマンドを実行したディレクトリの中だけです。隠しディレクトリとシンボリックリンクは探しません。`node_modules`、`vendor`、`build`、`dist`、`coverage`、`ios`、`android` も探しません。

探す範囲が2,000ディレクトリを超える場合や、ワークスペースの定義がない場合は、`--app` を指定するか、アプリのディレクトリで実行します。`--app` には、実行したディレクトリの中にあり、リンクではないディレクトリを指定します。

1. CLIがルートコンポーネントとGitHubリポジトリを検出します。
2. 初回のセットアップ時または明示的に再接続するときは、ブラウザでGitHubへログインし、送信先を確認して「接続」を押します。必要な場合のみ、GitHubで対象リポジトリへのアクセスを許可します。
3. CLIがSDKと依存関係をインストールし、ルートコンポーネントへKUEを追加します。
4. 変更の差分を確認してExpoを起動します。ネイティブ依存関係が追加された場合はdevelopment buildを再ビルドします。
5. レポートを送信し、[ダッシュボード](https://kue.ischca.dev/app)でレポートの処理状況とIssueを確認します。

接続承認リンクの有効期限は15分です。自分で開始したセットアップのみを承認してください。`init` の実行だけではIssueは作成されません。

接続が完了すると、URLが通常のダッシュボード（`/app`）に切り替わります。期限切れの接続リンクを開いた場合も、ログイン後にダッシュボードが表示されます。

セットアップ済みのプロジェクトを再接続する必要はありません。CLIのセットアップが未完了の場合のみ、`init` を再実行します。

接続先リポジトリのGitHub所有者からワークスペースが決まります。最初に接続したユーザーがKUEのワークスペース所有者になります。ワークスペースがすでにある場合、別のGitHub組織所有者にもKUEの管理権限が自動で付与されるわけではありません。

接続画面は、CLIが指定したリポジトリを固定して表示します。「接続」を押すと、対象リポジトリへのアクセスがすでに許可されていればそのまま接続します。許可されていなければ、同じタブでGitHubへ移動します。

個人アカウントまたは組織を選び、「Only select repositories」で対象リポジトリだけを許可できます。

GitHubからKUEへ戻ると、最初に指定した送信先の権限が再確認され、接続が完了します。接続ボタンをもう一度押す必要はありません。

GitHubで許可を保存した後、自動でKUEへ戻らない場合はブラウザの「戻る」で元の接続画面へ戻ります。この場合も、戻った時点で接続が再開されます。

KUEは接続を開始する操作を本人のブラウザ、ログイン中のアカウント、送信先に紐づけます。KUEはこの操作を有効期限内に一度だけ再開します。

GitHubでキャンセルした場合、別のリポジトリを許可した場合、組織の承認待ちの場合は接続しません。組織が承認した後は、「再読み込み」で確認し、「接続」を押します。

未完了のセットアップが期限切れの場合はCLIの `init` から再開します。GitHubでの許可操作は省略できません。

### initの再実行

KUEが管理する接続設定、組み込み、インストール済みの依存関係が変わっていなければ、通常の `init` はブラウザでの承認、パッケージマネージャーの実行、ファイルへの書き込みを行わずに終了します。ファイルの更新日時とlockfileも変わりません。

録画設定が `auto` の場合は、再実行のときにもCloudでプランを確認します。`off` の場合は確認しません。ローカルの状態とプランを確かめただけでは、送信できることは保証されません。

| 状態・指定 | 動作 |
| --- | --- |
| SDK更新 | CLIと同じSDKバージョンへ更新。接続設定と、互換性のある既存のネイティブ依存関係は維持。新しいSDKを古いCLIでダウングレードしない |
| 不足している依存関係 | 宣言されていないSDKと必須のネイティブ依存関係だけを追加。ネイティブ依存関係のバージョン範囲は、インストール済みのExpoの情報から決める |
| 依存関係の不整合 | 宣言済みだがインストールされていない場合や、バージョンが合わない場合は停止。先にlockfileから依存関係を復元するか、依存関係を自分で更新する |
| `--reconnect` | 明示的にブラウザ承認を行い、設定を再取得。送信先を変更するには `--repository OWNER/REPO`、サーバーを変更するには `--server URL` を併用 |
| `--config project.json` | 指定した設定だけを適用。同じ設定なら書き直さない。`--reconnect`、`--repository`、`--server` と併用不可 |
| `--skip-install` | 依存関係の確認・追加を行わない。依存関係が正しく導入済みであることを意味しない |
| `--sdk sdk.tgz` | ローカルtarballの内容ハッシュとインストール状態を比較。同じ入力なら再インストールしない。ローカルtarballを使い続ける場合も同じオプションを指定 |
| 管理対象ファイルの不整合 | JavaScriptの設定ファイルは実行しない。壊れた設定や組み込み、カスタマイズされた型宣言を勝手に初期化せず、停止する |

ブラウザでの承認後は、`.kue/setup.json` に設定のハッシュと接続先を保存します。ローカルtarballを使う場合は、同じファイルに内容ハッシュとSDKバージョンを保存します。

認証トークンや絶対パスは保存しません。このメタ情報はコミットできます。

旧設定などで接続先の記録がない場合、`--repository` を指定するには明示的な `--reconnect` が必要です。通常の再実行では、Git remoteが変わっても接続先を自動で変更しません。

必要なインストールを実行する場合、パッケージマネージャーが関連するlockfileを更新することがあります。差分を確認してください。明示的な `--reconnect` は毎回承認を要求します。

### オプション

| オプション | 動作 |
| --- | --- |
| `--dry-run` | 検出結果を表示。ネットワーク通信・ファイル変更なし |
| `--app apps/mobile` | 対象のExpoパッケージを指定。相対パスはコマンドの実行場所が基準 |
| `--repository OWNER/REPO` | 接続先のGitHubリポジトリを指定 |
| `--reconnect` | 明示的に接続設定を再取得。既存の送信先・サーバーを変更する場合も必要 |
| `--root app/_layout.tsx` | 組み込み先のルートファイルを指定 |
| `--no-open` | ブラウザを起動せず、接続承認リンクを表示 |
| `--config project.json` | ダッシュボードの接続設定（URLとプロジェクトキー）のJSONを使用。ブラウザでの接続承認を省略 |
| `--skip-install` | 依存関係のインストールを省略。必要なパッケージは別途追加 |
| `--skip-integration` | 既存の手動配置を維持し、JSXを読み書きしない。`--root` と併用不可 |
| `--recording auto\|off` | 録画モジュールを、プランに応じて組み込むか、明示的に除外する。デフォルトは `auto` |
| `--server https://YOUR-KUE-HOST` | Cloudの接続先を変更。デフォルトは `https://kue.ischca.dev` |
| `--sdk /path/to/sdk.tgz` | ローカル検証用のSDK tarballを指定 |

`--root` の相対パスは選択されたアプリが基準で、`--config` と `--sdk` の相対パスはコマンドの実行場所が基準です。依存関係と `.kue` は選択されたアプリ内に追加します。

CLIはアプリから親ディレクトリへ向かって `packageManager` とlockfileを確認し、パッケージマネージャーを判定します。

`--config` を指定した場合はJSON内の接続先を使用します。CLIの自動編集に対応しないルート構造では、手動でSDKを組み込みます。

### 生成ファイル

| ファイル | 内容・管理方法 |
| --- | --- |
| `.kue/config.js` / `.kue/config.d.ts` | 公開情報であるプロジェクトキーを含む接続設定と型定義。バージョン管理へ追加可能 |
| `.kue/backup-*.txt` | 変更前のアプリソース。ローカルで保管し、コミット対象から除外 |

GitHubユーザートークンや課金用の認証情報をアプリへ保存する処理はありません。

### 手動配置を維持するセットアップ

CLI 0.6.0では、独自のラッパーなどで既に `Kue` を配置しているアプリに `--skip-integration` を指定できます。CLIはJSXを読み書きせず、接続設定、依存関係、録画のビルド設定だけを管理します。`--skip-integration` は `--root` と併用できません。

```sh
kue-qa init --skip-integration
kue-qa init --skip-integration --reconnect
```

初回のみ、`.kue/config.js` の `kueCloudConfig` と `.kue/recording.js` の `kueRecordingMode` を既存の `Kue` に手動で渡します。CLIは手動配置の正しさを検証しません。

2回目以降の実行では接続設定を再利用し、設定と依存関係が同じならファイルを変更しません。`auto` モードではプランを読み取る通信が発生します。キーの再取得や送信先の変更には `--reconnect` を使用します。

新しいCLIがSDKを更新した後は、差分を確認して、アプリの既存の手順でビルドと配信を行います。録画の組み込みが変わった場合はネイティブの再ビルドが必要です。CLIはビルドやTestFlight／Google Playへの配信を開始しません。

## Expo SDKの手動導入

### パッケージの追加

SDK 0.6.0を導入します。アプリの既存のパッケージマネージャーを使用し、lockfileの形式を統一します。

```sh
npm install @kue-qa/react-native@0.6.0
npx expo install expo-application expo-constants expo-device expo-file-system expo-image-manipulator react-native-view-shot react-native-safe-area-context
```

### Cloud接続と配置

ダッシュボードの「導入設定を表示」で確認した接続設定（URLとプロジェクトキー）を `.env.local` に追加します。例に示したキーは対象プロジェクトのプロジェクトキーに置き換えます。GitHubトークンや秘密鍵は指定しません。

```dotenv
EXPO_PUBLIC_KUE_API_BASE_URL=https://kue.ischca.dev
EXPO_PUBLIC_KUE_PROJECT_KEY=pk_REPLACE_WITH_PROJECT_KEY
```

アプリのルートに `Kue` を1つ配置します。次の例はExpo Routerの `app/_layout.tsx` です。

```tsx
import { Stack } from 'expo-router';
import { Kue } from '@kue-qa/react-native';

export default function RootLayout() {
  return (
    <>
      <Stack />
      <Kue cloud={{
        apiBaseUrl: process.env.EXPO_PUBLIC_KUE_API_BASE_URL!,
        projectKey: process.env.EXPO_PUBLIC_KUE_PROJECT_KEY!,
      }} />
    </>
  );
}
```

`Slot` を使用する構成では `Stack` を `Slot` に置き換えます。Expo Routerを使用しない場合は、アプリのルートコンポーネントに `Kue` を配置します。

環境変数を読み取るのはアプリ側の処理です。SDKが環境変数を自動で読み取ることはありません。

### 独自の保存処理

`onSubmit` は `KueLocalReport` を受け取り、`void` または `Promise<void>` を返します。次の例の `saveReportAndCopyImage` はアプリ側で実装する保存関数です。`submitLabel` には、送信ボタンに表示する操作名を指定します。

```tsx
<Kue
  onSubmit={async (report) => {
    await saveReportAndCopyImage(report);
  }}
  submitLabel="Save report"
/>
```

`cloud` か `onSubmit` のどちらかを指定します。どちらも指定しない場合は、型検査でエラーになります。`onSubmit` と `cloud` を両方指定した場合は `onSubmit` が優先されます。この場合、Cloudへの送信とオフラインキューは使用されません。

送信先を条件によって切り替える場合は、`KueDestination` 型の値を1つ選び、`Kue` に展開します。

`onSubmit` または `onSubmitGroup` を指定する場合は `submitLabel` が必要です。指定しない場合は、型検査でエラーになります。

指定した表記は編集画面、長押しメニュー、確認画面で使います。件数の「（N件）」はSDKが付けます。`cloud` だけを指定した場合は「Issueを作る」と表示し、`submitLabel` は指定できません。

`cloud` と `onSubmitGroup` を指定した場合、保存した指摘がないときはCloudへ送信するため、「Issueを作る」と表示します。型検査を通さずに `submitLabel` を省略した場合は「送信」と表示し、警告を1回出力します。

画像URIは一時ファイルを参照します。コールバックの完了後も画像が必要な場合は、コールバックのPromiseが完了する前に画像をコピーまたはアップロードします。

| `KueLocalReport` のフィールド | 内容 |
| --- | --- |
| `clientReportId` | 同じ送信内容の再試行で維持する識別子 |
| `memo` | 入力されたメモ |
| `crop` | 正規化された範囲座標 `x`・`y`・`width`・`height` |
| `screenshot` | 切り取った画像のURI、幅、高さ、MIMEタイプ |
| `sourceSize` | 元画像の幅・高さ |
| `context` | 端末・アプリのメタ情報 |
| `capturedAt` | キャプチャ日時 |

## ExpoのキャプチャとIssue作成

### 操作手順

1. KUEボタンをタップします。

   ![画面の右下にKUEボタンがあるアプリの画面](images/kue-button.webp)

2. 枠の角をドラッグして範囲を選択し、メモを入力します。

   ![範囲の枠とメモ欄、「指摘を追加」と「Issueを作る」のボタンがある編集画面](images/finding-screen.webp)

3. レポートに秘密情報や個人情報が含まれていないことを確認し、「Issueを作る」を選びます。ほかの指摘とまとめて送る場合は、代わりに「指摘を追加」を選びます。手順は「複数指摘のまとめ送信」で説明します。
4. Cloudと連携している場合は、ダッシュボードでレポートの処理状況と作成されたIssueを確認します。

### フローティングボタン

デフォルトはファインダー形のボタンです。キャラクターを表示するには `buttonDesign="mascot"` を指定します。

どちらのデザインでも操作方法とタッチ領域は同じです。キャラクターの画像はSDKに同梱されており、追加のダウンロードやネイティブ依存関係は不要です。

```tsx
<Kue cloud={cloud} buttonDesign="mascot" />
```

![デフォルトのファインダー形のKUEボタン（左）と、キャラクターのKUEボタン（右）](images/button-designs.webp)

| 操作 | 結果 |
| --- | --- |
| タップ | キャプチャを開始 |
| ドラッグ | 位置を移動。キャプチャは開始しない |
| 画面端で離す | ボタンを隠して小さなハンドルにする |
| ハンドルをタップ | ボタンを再表示 |
| 約0.5秒長押しして項目の上で離す | メニューの操作を選択。メニューに表示する項目がない場合は、タップと同じくキャプチャを開始 |

ボタンの位置はアプリの再起動後に引き継がれません。

### 表示言語

KUEの画面は日本語と英語で表示できます。

端末で優先する言語の一覧で、英語より先に日本語がある場合は日本語、それ以外の場合は英語で表示します。iOSでは端末の言語設定（アプリごとの言語を含む）を参照し、Androidではアプリに適用されている言語を参照します。

表示言語を固定するには、`locale` に `"ja"` または `"en"` を指定します。

```tsx
<Kue cloud={cloud} locale="en" />
```

`submitLabel` に指定した表記は、表示言語にかかわらずそのまま表示します。KUE Cloudへの送信で起きたエラーの説明は、表示言語にかかわらず英語です。

### Issueの内容

Issueには切り取った画像、メモ、端末・アプリのメタ情報が含まれます。

デフォルトのラベルは `kue` です。ラベルが存在しない場合はKUEが作成し、既存のラベルの設定は変更しません。ラベル名のカスタマイズには対応していません。

### 複数指摘のまとめ送信

複数の画像や動画を1つのIssueにまとめて送信できます。本番Cloudはまとめ送信に対応しています。

1. 1件目の編集画面で「指摘を追加」を選びます。指摘は送信されず、端末の下書きに保存されます。KUEボタンには保存した指摘の件数が表示されます。
2. アプリの操作を続け、KUEボタンをタップして次の指摘を記録します。
3. 最後の編集画面で「Issueを作る（N件）」を選びます。Nは保存した指摘と表示中の指摘の合計です。編集画面が閉じた後、確認画面が開きます。
4. 確認画面で画像とメモを確認し、不要な指摘を削除します。タイトルの初期値は1件目のメモの最初の行です。必要に応じてタイトルを変更し、「Issueを作る（N件）」を選びます。

   ![タイトル欄と2件の指摘が並ぶ確認画面](images/confirmation-screen.webp)

保存した指摘がない場合、「Issueを作る」は表示中の指摘だけを送信します。この場合、確認画面は開きません。

「指摘を追加」は `onSubmit` を指定せずに `cloud` を指定した場合と、`onSubmitGroup` を指定した場合に表示されます。

保存した指摘だけでIssueを作る場合は、KUEボタンを約0.5秒長押しし、開いたメニューの「Issueを作る（N件）」の上で指を離します。新しいキャプチャは作成せず、確認画面を開きます。この項目は、保存した指摘がある場合だけ表示されます。

![長押しで開いたメニュー。「Issueを作る（1件）」を選択中](images/long-press-menu.webp)

長押しメニューにはタップではできない操作だけを表示します。

| 項目 | 表示する条件 |
| --- | --- |
| Issueを作る（N件） | 保存した指摘がある場合 |
| 画面録画 | `cloud` を指定し、`recording` が `off` 以外の場合。`onSubmit` を指定する場合は `onSubmitGroup` も必要。Freeでは「画面録画 · Indieで解放」と表示し、選ぶとIndieの利用条件を案内 |
| 送信待ち | オフラインキューが有効な場合 |

項目はKUEボタンの近くに並び、各項目の横に名前を表示します。名前は画面の端やほかの項目に隠れない位置に表示し、収まらない場合は一覧で表示します。

項目のボタンか名前の上で指を離すと、その操作を選びます。KUEボタンの上や項目のない場所で指を離すとキャンセルします。

メニューが開く前にドラッグした場合は、ボタンを移動します。画面回転・バックグラウンドへの移行・複数の指での操作でも選択をキャンセルします。

TalkBack／VoiceOverの「操作メニューを表示」では一覧から選択できます。表示する項目がない場合、長押しはタップと同じくキャプチャを開始します。

指摘を10件保存している場合や、保存した指摘の送信結果が確定していない場合も、KUEボタンのタップ、トリガー、`reportIssue()` はキャプチャを開始します。

表示中の指摘は下書きに追加できないため、編集画面には「指摘を追加」の代わりに「保存した指摘を開く」と、その理由を表示します。「Issueを作る」を選ぶと、表示中の指摘だけを送信します。

「保存した指摘を開く」を選ぶと、表示中の指摘を残したまま確認画面を開きます。

確認画面で保存した指摘を送信・再送・破棄するか、「戻る」を選ぶと、編集画面に戻ります。画像の範囲とメモは保持されます。戻ったときに表示中の指摘を下書きへ追加できる場合は、「指摘を追加」を表示します。

下書きに指摘を追加できない状態で長押しメニューの「画面録画」を選ぶと、録画を開始せずに確認画面を開きます。

FreeとIndieのどちらも、まとめて送れる指摘は1〜10件、画像は1件あたり10 MiB・合計20 MiBまでです。

利用量はIssueの数ではなく指摘の数で数えます。指摘3件をまとめて送ると、3件分を消費します。

受付は全件を一括で行い、上限を超えた場合や保存に失敗した場合も、一部の指摘だけを受け付けることはありません。

下書きはアプリのセッション中のみ保持し、画像はSDK専用の一時領域へコピーします。下書きはアプリの終了後に復元されません。オフラインキューへ移されることも、自動で送信されることもありません。

送信先のキーやサーバーを変更しても、既存の下書きを別の送信先へ移しません。

アプリの終了や再読み込みで残った下書きのコピーは、次にKUEが有効な状態でアプリを起動したときに削除します。

一度送信を試みた後は内容を固定します。再送では同じ識別子と内容を使用します。受付結果が不明なまま新しい識別子で送り直すことはありません。

端末側の下書きを破棄しても、すでに受け付けられたIssueの作成は取り消されません。

プランをまだ確認できていない状態で確認に失敗した場合、「画面録画」はFreeのロック表示にならず、選ぶと通信状態の確認と再試行を案内します。確認済みのプランがある場合は、再確認に失敗してもそのプランの表示を続けます。

### 画面録画

画面録画には録画対応のネイティブビルド、`cloud` の指定、有効なIndieプランの契約が必要です。`onSubmit` を指定する場合は `onSubmitGroup` も必要です。本番Cloudは動画の受付に対応しています。

1. KUEボタンの長押しメニューから「画面録画」を選び、OSが表示する録画許可を確認します。
2. 録画中はKUEボタンが同じ位置で赤い四角の停止ボタンに変わります。タップすると録画を停止します。停止ボタンは移動できますが、画面端で隠す操作と長押しメニューは無効です。Androidでは録画通知からも停止できます。
3. 録画を停止した後、「動画を再生」で動画を確認します。指摘内容を入力し、「下書きに追加して確認」を選びます。この時点では送信しません。録画を保存しない場合は「録画を破棄して戻る」を選びます。
4. Issueのタイトルと指摘を確認して送信します。戻って画像や動画を追加することもできます。

録画は無音のH.264 MP4形式です。長さは最大60秒、サイズは最大20 MiBです。音声もマイクの入力も収録しません。

時間または容量の上限に達する前に、余裕を持って自動停止します。アプリがバックグラウンドに移ったとき、画面がロックされたとき、OSがアプリを終了したときにも録画を停止します。iOSで録画中に画像の縦横サイズが変わった場合も停止します。

保護された画面は録画できない場合があります。

動画1件は指摘1件として数えます。画像と動画は混在できます。上限は両方を合わせて10件、合計20 MiBです。

動画もセッション中に一時保存するだけで、オフラインキューには入りません。

送信前にプランがFreeへ戻った場合は、動画を含むグループ全体が拒否されます。一部だけが送信されることはありません。

録画開始時と受付時にプランを確認します。受付済みの内容と同じ内容を再送しても、新しい利用としては数えません。

Issueには動画を開くリンクを記載します。動画のURLを知っている人は閲覧できるため、機密情報を録画しないでください。

動画にも画像と同じ保存容量、保管期限、削除のルールを適用します。動画の切り取りと編集には対応していません。

### 録画のビルド設定

CLI 0.6.0は録画モジュールを組み込むかどうかを管理します。

録画設定は対象アプリの `package.json` の `kue.recording` で指定します。デフォルト値は `auto` です。

`init` は接続先ワークスペースのプランを確認します。Freeでは録画用ネイティブモジュールを除外し、Indieでは組み込み対象に設定します。

`off` を指定した場合は、プランにかかわらず録画用ネイティブモジュールを除外します。スクリーンショット用の依存関係は除外しません。

```sh
kue-qa init
kue-qa init --recording off
kue-qa init --recording auto
kue-qa check
```

1. 初回は `init` を実行します。`auto` ではブラウザでの承認の有無にかかわらず、Cloudからプランを読み取って確認します。録画をオフにする場合は `--recording off` を指定します。指定した録画設定は、次回以降の実行でも保持します。
2. プランまたは録画設定を変更した場合は、再度 `init` を実行して差分を確認します。プラン、設定、依存関係が同じ状態で再実行した場合は、ファイルの内容も更新時刻も変更しません。通信、認証、応答の検証のいずれかに失敗した場合は、Freeとして扱いません。この場合は既存の設定を保持し、エラーで終了します。
3. 録画のビルド設定が変わった場合は、アプリの通常のビルド方法で再ビルドします。CLIはビルドや配布を自動で開始しません。Expo Goに独自の録画モジュールを追加することはできません。
4. 管理対象の設定を読み取る `check` を実行し、プラン、設定、ネイティブの組み込み対象の間に不一致がないかを確認します。不一致がある場合はエラーになり、設定を自動で修復することはありません。`--config`・`--env` はCloudへ送信できるかどうかだけを検証し、アプリの録画ビルド設定は検証しません。

通常のネイティブビルドでは、保存済みの録画のビルド設定を使います。Cloudへのプランの問い合わせや設定の変更は行いません。

`package.json`、`.kue/recording.js`・`.d.ts`、`.kue/setup.json` とアプリルートの変更をコミットします。生成ファイルは直接編集しません。

`--dry-run` は通信も変更も行わないため、最新プランの確認にはなりません。`--skip-install` は依存関係のインストールだけを省略し、`auto` でのプランの確認と設定の更新は行います。

設定を更新しても、インストール済みのアプリは変わりません。録画に対応したビルドが必要な場合は、プランの説明を繰り返さずに再ビルドの案内を表示します。

Freeでのロック、通信の失敗、`off` の指定、Cloudでの未提供は、それぞれ別の状態として表示します。

録画のビルド設定をしても、録画を使えるプランになるわけではありません。録画の開始と送信には、別途Cloud側の確認が必要です。

### ビルド前に送信できるか確認する

配布ビルドの前に、対象アプリの管理対象設定を使って、送信できるかどうかを確認します。

```sh
npx kue-qa@0.6.0 check
```

`--app` は対象アプリを選択します。代わりに `--config project.json` でダッシュボードの設定JSON、または `--env` でビルド環境が解決済みの `EXPO_PUBLIC_KUE_MODE`、`EXPO_PUBLIC_KUE_API_BASE_URL`、`EXPO_PUBLIC_KUE_PROJECT_KEY` と任意の `EXPO_PUBLIC_KUE_ENABLED` を使用できます。これら3種類の設定入力は併用できません。

キーをコマンド引数に直接指定しないでください。`--env` はdotenvを読み込まないため、Expo/EASのビルド環境で使用する値を先に解決します。

`check` は認証付きGETで、現在のキー、プロジェクトがレポートを受け付けられる状態か、利用枠・保存容量、Issue作成の設定を確認し、許可された場合に終了コード0を返します。拒否、通信・タイムアウト、未対応サーバー、無効な応答の場合は0以外で終了します。タイムアウトは10秒です。

設定や利用枠は変更せず、レポートやIssueも作りません。ローカルモードを指定した場合と `EXPO_PUBLIC_KUE_ENABLED=false` の場合は、通信を省略します。設定不足は成功として扱いません。

管理対象設定の場合は、録画モジュールの組み込みと現在のプランも照合します。`--config`・`--env` では、Cloudへ送信できるかどうかだけを確認します。

成功してもGitHubの権限、キューや保存先の稼働、実機キャプチャ、確認後のキー失効や利用枠の変化は保証しません。配布ビルドで実際の送信を確認してください。

### まとめ送信・録画API

| API | 入力・戻り値・制限 |
| --- | --- |
| `onSubmitGroup` | `KueReportGroup` を受け取る独自保存処理。`onSubmit` を指摘の数だけ呼ぶ処理には置き換えない。Promiseが解決するまでに、必要な画像・動画をコピーまたは送信する。`submitLabel` が必要 |
| `submitKueReportGroup(group, cloud)` | `clientReportId`・`title`・順序付き `findings` を一括送信し、1つの `KueReceipt` を返す。まとめ送信に非対応のサーバーでも、1件ずつの送信には切り替えない |
| `getKueProjectFeatures(cloud)` | まとめ送信の対応状況のほか、録画を使えるプランかどうかと、Cloudでの提供状況を返す。認証や通信に失敗した場合は例外になる。クライアント側のプラン指定は受け付けない |
| `KueProps.recording` | `"auto" \| "off"`。デフォルト値は `auto`。`off` は実行時の録画を無効化し、長押しメニューに「画面録画」を表示しない。ネイティブ部分の除外はCLIのビルド設定で行い、このPropだけではネイティブ部分をバイナリから削除しない |

`KueReportGroup.findings` は `KueFinding`（`KueLocalReport | KueVideoReport`）の配列です。`KueVideoReport` は `clientReportId`・`memo`・`context`・`capturedAt` と `video` を持ちます。`video` は `uri`・`width`・`height`・`durationMs`・`byteSize`・`mimeType: "video/mp4"`・`capturedAt` を持ちます。

各メディアのURIは、送信が完了するまで有効な状態に保つ必要があります。

カスタムの `onSubmit` を使用する場合、まとめ送信には別途 `onSubmitGroup` を指定します。下書きは作成時のハンドラーを保持します。再レンダーで別の関数が渡されても、既存の下書きがその関数へ移ることはありません。

## Expo SDK設定リファレンス

### KueProps

`cloud` か `onSubmit` のどちらかを指定します。ほかのPropsは省略可能です。

`KueProps` は型エイリアスのため、拡張する場合は `type Props = KueProps & { … }` のように交差型で書きます。

| Prop | デフォルト値 | 動作 |
| --- | --- | --- |
| `enabled` | `__DEV__` | SDKの有効・無効。リリースビルドではデフォルトで無効 |
| `cloud` | 未指定 | `KueCloudConfig` でCloud送信を設定。`onSubmit` を指定しない場合は必須 |
| `onSubmit` | 未指定 | 独自の保存処理を行うコールバック。`cloud` より優先。`submitLabel` が必要 |
| `onSubmitGroup` | 未指定 | まとめた指摘を受け取る独自の処理。`submitLabel` が必要 |
| `submitLabel` | 未指定 | 独自の送信処理のボタンに表示する操作名。`onSubmit` または `onSubmitGroup` を指定する場合は必須。`cloud` だけの場合は指定できない |
| `context` | `{}` | 自動取得したメタ情報を補完・上書き |
| `floatingButton` | `true` | ボタンの表示。`false` でも他の起動方法は使用可能 |
| `buttonDesign` | `"classic"` | `"classic"` はファインダー形のボタン、`"mascot"` はキャラクターボタン |
| `locale` | 端末の言語 | KUEの画面の表示言語。`"ja"` または `"en"`。省略すると端末で優先する言語に従う |
| `triggers` | 未指定 | 追加の起動処理を登録する配列 |
| `offlineQueue` | `false` | Cloudへの送信待ちレポートを端末に保存する機能を有効化 |
| `onQueued` | 未指定 | 端末に保存した後、Cloudがまだ受け付けていない場合に `clientReportId` を通知 |
| `onReceipt` | 未指定 | Cloudが受け付けた後に `KueReceipt` を通知 |
| `onError` | 未指定 | キャプチャ・送信エラーを通知。未指定の場合はアラートを表示 |
| `capture` | SDK標準のキャプチャ処理 | `KueCaptureAdapter` でキャプチャ処理を置き換え。テスト・独自実装向け |

社内QA用のリリースビルドでSDKを有効にする場合は、アプリ側で決めた条件で `enabled` を設定します。一般配布ビルドで無条件に有効にすることは避けてください。

### KueCloudConfig

| プロパティ | 必須・デフォルト値 | 内容 |
| --- | --- | --- |
| `apiBaseUrl` | 必須 | 認証情報、パス、クエリ、フラグメントを含まないCloudのURL（origin）。`/v1/reports` を付けない |
| `projectKey` | 必須 | `pk_` に8〜128文字の英数字・`_`・`-`が続く公開プロジェクトキー。送信とプロジェクト機能の確認に使用。管理権限やレポート閲覧権限ではない |
| `timeoutMs` | デフォルト `15000` | HTTPリクエストのタイムアウト（ミリ秒）。1〜120000の整数 |

### メタ情報

KUEはOS、端末モデル、アプリのバージョンとビルド番号、画面サイズを自動で取得します。取得できる場合はExpo Updatesの情報も含めます。端末ID、個人の端末名、画面のルートは自動では取得しません。

アプリ固有の情報は `context` に指定します。次はExpo Routerのルートテンプレートを渡す例です。

```tsx
import { useSegments } from 'expo-router';
import { Kue, type KueCloudConfig } from '@kue-qa/react-native';

export function QaReporter({ cloud }: { cloud: KueCloudConfig }) {
  const segments = useSegments();
  return <Kue cloud={cloud} context={{ route: `/${segments.join('/')}` }} />;
}
```

この例を使用する場合は、`Kue` を重複して配置しません。

メタ情報は自動取得値 → `context` → `reportIssue({ context })` の順に適用され、後の値が優先されます。URLクエリやユーザーIDではなく、匿名化したルートテンプレートを指定します。

## Expoの起動APIとトリガー

### reportIssue

`reportIssue(options?): Promise<void>` は、配置済みで有効なKUEの編集画面を開きます。`options.memo` は初期メモ、`options.context` はレポート単位のメタ情報です。

```ts
import { reportIssue } from '@kue-qa/react-native';
await reportIssue({ memo: 'Describe the issue' });
```

有効なKUEが存在しない場合は `KueUnavailableError` で失敗します。このAPIはレポートを送信しません。戻り値に受付情報は含まれません。

### シェイク・スクリーンショット

追加のトリガーは任意です。使用するモジュールを追加し、development buildを再ビルドします。

```sh
npx expo install expo-sensors expo-screen-capture
```

```tsx
import { shakeTrigger } from '@kue-qa/react-native/shake';
import { screenshotTrigger } from '@kue-qa/react-native/screenshot';

const triggers = [shakeTrigger, screenshotTrigger];
<Kue cloud={cloud} triggers={triggers} />
```

`cloud` は設定済みの `KueCloudConfig` です。トリガーの配列はコンポーネントの外などで定義し、参照が変わらないようにします。`floatingButton={false}` でボタンのみ非表示にできます。

| トリガー | 依存モジュール | 対応・動作 |
| --- | --- | --- |
| `shakeTrigger` | `expo-sensors` | シェイクを検知して編集画面を開く |
| `screenshotTrigger` | `expo-screen-capture` | iOS、およびAndroid 14以降。OSのスクリーンショットを検知し、現在のアプリ画面をもう一度キャプチャ |

トリガーが検知を行うのは、KUEが有効で、アプリがフォアグラウンドにあり、KUEの画面を開いていないときです。トリガーは写真ライブラリを読み取らず、レポートを自動で送信することもありません。

### Android権限

KUEは追加の権限を要求せず、アプリ内で共有されるセンサーの取得間隔も変更しません。

オプションのExpoモジュールは `ACTIVITY_RECOGNITION`、`READ_EXTERNAL_STORAGE`、`READ_MEDIA_IMAGES` を追加します。これらの権限はアプリのほかの機能で不要な場合に限り `android.blockedPermissions` で除外できます。Android 14以降のスクリーンショット検知に必要な `DETECT_SCREEN_CAPTURE` は維持します。

## Expoのオフラインキュー

### 有効化

`offlineQueue` はCloud送信専用のオフラインキューです。デフォルトでは無効です。`onSubmit` による独自保存は対象外です。

```tsx
<Kue cloud={cloud} offlineQueue />
```

送信前にレポートをアプリ内の `Documents/kue-outbox-v1` へ保存します。追加のネイティブ依存関係や権限は不要で、アプリ側でDBを設定する必要もありません。

### 保存上限と再試行

| 項目 | 値・動作 |
| --- | --- |
| 件数 | 全送信先を合計して10件 |
| 合計容量 | 50 MiB |
| 画像1枚 | 10 MiB以下 |
| 保存期限 | 7日。期限を過ぎた項目は次にキューへアクセスしたときに削除 |
| 自動再試行 | アプリがフォアグラウンドにある間に実行。終了中またはバックグラウンドでの実行は保証しない |
| 通信エラー | しばらく待ってから再試行 |
| 無効なキー・利用上限 | 自動再試行を停止し、手動での操作を待つ |

接続先やキーを変更しても、既存の項目は新しい送信先へは自動で送られません。

レポートが端末にだけ保存され、Cloudがまだ受け付けていない場合は `onQueued` に通知されます。Cloudが受け付けた後は `onReceipt` に通知されます。

### 管理API

以下の関数は `@kue-qa/react-native` からインポートします。`cloud` は対象の接続設定、`id` は一覧の `clientReportId` です。

| API | 結果 |
| --- | --- |
| `pendingKueReports(cloud)` | 送信待ちレポートの識別子、保存日時、状態を取得 |
| `retryPendingKueReports(cloud, { force: true })` | 手動で再試行。戻り値は `Promise<void>` |
| `discardPendingKueReport(cloud, id)` | 端末内の対象項目を破棄 |

SDK独自の暗号化はありません。バックアップはホストアプリの方針に従います。端末側で破棄しても、Cloudがすでに受け付けたデータは取り消されません。

## 更新とアンインストール

### Expo SDKの更新

次のコマンドはExpo SDKとCLIを公開済みの0.6.0へ更新します。別のバージョンを使用する場合は、公開済みバージョンと変更履歴を確認してから、バージョン番号を置き換えます。

```sh
npm install @kue-qa/react-native@0.6.0
```

CLIでSDKを更新する場合は、対象バージョンを指定します。CLIは既存の接続設定を再利用します。設定を再取得する場合だけ `--reconnect` を追加します。

```sh
npx kue-qa@0.6.0 init
```

CLIは自身と同じバージョンのSDKを使用します。CLIより新しいSDKを暗黙にダウングレードすることは拒否します。変更がなければ `init` は何も書き換えません。更新時は差分を確認してください。

更新コマンドを実行していない間に、SDKが自動で更新されることはありません。

依存関係やネイティブモジュールを変更した場合は、development buildを再ビルドし、実機でキャプチャと送信を確認します。依存関係のバージョンはアプリのlockfileで管理します。

### アンインストール

1. 端末内の送信待ちレポートを送信または破棄します。
2. `Kue`、アプリ独自のトリガー、接続設定をアプリから削除します。
3. SDKをアンインストールします。Expoの依存パッケージのうちほかの機能と共有しているものは、ほかの機能で使われていないかを確認してから削除します。

SDKのアンインストールでは、CloudプロジェクトやGitHub Issueは削除されません。

## Expoのトラブルシューティング

### Expoのビルドと配布の接続設定

Cloudへの送信に使う接続設定（URLとプロジェクトキー）は、実際にアプリへ埋め込むビルド環境で確認します。

ローカルの `.env.local` を変更しても、EAS側の環境変数や配布済みアプリは更新されません。ビルド環境に同名の環境変数が設定されている場合は、その環境変数がローカルファイルより優先されます。

キーを再発行した場合やプロジェクトを作り直した場合は、利用する各ビルド環境の設定を更新し、アプリを再ビルドして配布します。別のリポジトリのキーで代用しないでください。

既存の送信待ちレポートは新しいキーへ自動で移行されません。

CLI 0.6.0の `init` が完了しても、送信できることは保証されません。録画設定が `auto` の場合はプランを確認しますが、Issueの作成や今後の利用枠までは確認しません。

配布前に `kue-qa check` とダッシュボードで、対象プロジェクトが送信を受け付けられる状態かを確認し、実際の配布ビルドで送信を検証してください。確認後にキーが失効したり利用枠が消費されたりすると、後から送信できなくなる場合もあります。

### Expo SDKエラー

Cloud通信エラーは `KueCloudError.code` で分類します。HTTP応答がある場合は `status`、サーバーのエラーコードがある場合は `serverCode` も取得できます。

| `code` | 分類 |
| --- | --- |
| `invalid_config` | 接続設定が不正 |
| `invalid_report` | 送信データが不正 |
| `network_error` | ネットワーク通信の失敗 |
| `request_timeout` | リクエストのタイムアウト |
| `unexpected_response` | 応答形式が想定外 |
| `upload_rejected` | サーバーがリクエストを拒否 |
