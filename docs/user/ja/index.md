# KUE ドキュメント

KUEはExpo、ネイティブiOS／Android、Flutter、Expoを使わないReact Nativeのアプリに、画面キャプチャ、範囲選択、メモ入力の機能を組み込むSDKです。レポートの送信先にはGitHub Issueを作成するKUE Cloudか、アプリ側の保存処理を指定します。

対象バージョン: SDK・CLI **0.6.0**。Expo向けとExpoを使わないReact Native向けのパッケージ、およびCLIはnpmで配布しています。Flutterのcore・recorderはpub.devで配布しています。

ネイティブiOSはSwift Package Managerで`v0.6.0`タグ、またはGitHub ReleaseのZIPを使用します。ネイティブAndroidはMaven Centralから導入します。これまでのAndroid Maven ZIP版（グループID `dev.kue.qa`）も引き続き使えます。

Cloudの利用条件は現在の本番環境のものです。録画を使うには、Indieプランの契約に加えて、録画モジュールを含むネイティブビルドが必要です。

## 動作要件

| 項目 | 対応範囲 |
| --- | --- |
| Expo SDK | Expo SDK 54〜57／iOS・Android。`@kue-qa/react-native` |
| ネイティブiOS | UIKit／SwiftUI、iOS 15以上、Swift 5.9以上 |
| ネイティブAndroid | Views／Compose、Android 8／API 26以上、Kotlin／JVM 17 |
| Flutter | Flutter 3.32以上／Dart 3.8以上、iOS 15以上／Android API 26以上 |
| React Native（Expoなし） | RN 0.86.2、React 19.2.3、New Architecture、iOS 15.1以上／Android API 26以上 |
| OS | iOS・Android。Webの画面キャプチャは非対応 |
| CLI | Node.js 22.13以上。自動セットアップはExpoアプリのみ |
| ライセンス | SDK・CLI: MIT。Cloud: 別途提供するクラウドサービス |

Expo SDK 57のアプリをXcode 27（iOS 27 SDK）でビルドする場合は、`expo@57.0.23`以降を使用し、`expo-build-properties`の`ios.enableSceneSupport`を`true`に設定してiOSプロジェクトを再生成します。この設定なしでiOS 27 SDKを使ってビルドしたアプリは、iOS 27で起動できません。

Cloudと連携するには、GitHubアカウントと、送信先リポジトリへのKUE QA GitHub Appのインストールが必要です。接続するユーザーは個人リポジトリの所有者または組織の所有者であり、対象リポジトリの管理権限も持つ必要があります。

Appをインストールできない場合の連絡先は[サポート](mailto:kue@ischca.dev)です。

`onSubmit` による独自保存はCloudアカウントなしで利用できます。

## ワークスペース管理と送信状態

### ワークスペースと権限

ワークスペースは契約、プロジェクト、利用量の単位で、1つのGitHub個人アカウントまたは組織に対応します。別のGitHub所有者のリポジトリは別のワークスペースに属します。

リポジトリを改名しても、所属するワークスペースは変わりません。GitHub上でリポジトリを別の所有者へ移管しても、KUEでの所属は自動では変わりません。

管理操作をするには、自分のGitHubアカウントでのログイン、KUEのワークスペースのメンバー権限、現在のGitHub所有者権限が必要です。プロジェクトキーは管理権限を付与しません。

テスターや端末の数による追加料金はありませんが、所有者や顧客が異なる業務を1つの契約にまとめることはできません。メンバー招待には対応していません。

### ダッシュボード

[ダッシュボード](https://kue.ischca.dev/app)を初めて開いたときは、リポジトリの接続画面を表示し、空のワークスペース選択欄は表示しません。リポジトリの一覧は自動で取得します。一覧に対象のリポジトリがなければ、「接続」からGitHubで許可します。

CLIを経由せずにダッシュボードを開いた場合は、送信先が指定されていません。そのため、ダッシュボードに戻った後でリポジトリを選び、「接続」を押します。

一覧にないリポジトリを追加する場合は、「GitHubのアクセス権を設定」を使います。リポジトリを接続すると、ワークスペースが自動で作成されます。

接続後は対象ワークスペースを選択し、接続設定（URLとプロジェクトキー）、プラン、当月の送信数、画像容量、直近20件のレポートを確認します。課金に関する操作、ワークスペースの削除、所有者の移管は、KUEのワークスペース所有者だけが実行できます。

| 操作 | 影響 |
| --- | --- |
| 「導入設定を表示」 | 接続済みプロジェクトのSDK設定を表示 |
| 「プロジェクトキーを再発行」 | 旧キーを失効させる。キーを使っているすべてのアプリで設定の更新が必要。既存のIssueはそのまま残る |
| 「再試行」「GitHub Issueを再確認」 | 「再試行」は失敗したレポートを処理し直す。Issueが作成されたか分からない場合は、「GitHub Issueを再確認」で既存のIssueがあるかを確かめる |
| 「Freeで使うプロジェクトに選ぶ」 | 送信できるプロジェクトを1つ選ぶ。選ばなかったプロジェクトの休止は、削除とは別の状態 |
| プロジェクトの削除 | 送信を停止し、画像とレポートを順に削除。GitHub Issueは削除しない |

### 購入・解約

1. ダッシュボードで対象ワークスペースを確認します。[料金ページ](https://kue.ischca.dev/pricing)と[利用規約](https://kue.ischca.dev/terms)で利用枠、保存期間、解約と返金の条件を確認します。「Indieにアップグレード」からStripe Checkoutを開きます。最終金額・決済通貨・月額の自動更新を確認して、規約に同意してから購入します。
2. ダッシュボードで、プランがIndieに変わったことと契約期限を確認します。反映が遅れる場合は「契約状態を更新」を押します。購入画面から戻っただけでは、契約が反映されたことを確認できません。
3. 支払方法、請求書、解約は、「支払い・解約を管理」から開くStripe Customer Portalで操作します。次回の更新より前に解約すると、支払い済みの契約期間が終わった時点でFreeへ戻ります。

契約は毎月自動で更新されます。請求の周期と、月間送信枠の更新日は別です。

支払いに失敗して有効な契約を確認できない場合は、Freeの制限が適用されます。支払方法を修正したあと、「契約状態を更新」を押します。

プロジェクトを削除したりSDKをアンインストールしたりしても、契約は解約されません。

決済にはStripe Managed Paymentsを利用します。Checkoutでは表示と決済が現地通貨になる場合があります。

領収書・請求書はLinkから届きます。注文、契約、支払方法は、KUEの「支払い・解約を管理」に加えて、Linkでも管理できます。

返金については、購入時に提示されるLinkの条件が優先する場合があります。法令上の権利は制限されません。

Linkにデータの削除を請求すると、契約が終了する場合があります。KUEの画像とレポートを削除する場合は、別途KUEで操作します。

### 所有者の移管

ダッシュボードで移管できるのは、Stripeの課金アカウントがまだ作成されていないFreeの組織ワークスペースだけです。個人ワークスペースと、Checkoutを開始して課金アカウントが作成されたワークスペースは対象外です。これ以外の場合に所有者を変更するときは、サポートへ連絡してください。

1. 移管先のユーザーが自分のGitHubアカウントでKUEへログインします。承認する時点で、移管先のユーザーにはGitHub組織の所有者権限が必要です。
2. 現在のKUE所有者がダッシュボードで移管先のGitHubユーザー名と確認用の組織名を入力して申請します。
3. 移管先のユーザーが自分のダッシュボードで組織名を確認し、24時間以内に承認します。申請者は申請を取り消せます。移管先のユーザーは辞退できます。

移管の申請中は購入を開始できません。

移管が完了すると、元の所有者はKUEの管理権限を失います。プロジェクト、プロジェクトキー、利用数はそのまま引き継がれます。新しい所有者は必要に応じてプロジェクトキーを再発行してください。この移管はGitHub上の組織所有者そのものを変更する操作ではありません。

### ワークスペースの削除・退会

1. 契約がある場合は、先に解約して契約の終了を待ちます。未完了のCheckoutがある間や課金の確認中は、ワークスペースを削除できません。
2. 対象ワークスペースの削除操作で、GitHub所有者名を入力して確認します。削除すると、そのワークスペースの全プロジェクトで、送信とKUE経由の画像アクセスが停止します。
3. 所有するすべてのワークスペースについて、削除が完了した後または移管した後に、折りたたまれた「アカウント削除」を開きます。自分のGitHubユーザー名を入力して退会します。

処理中の送信に対する15分の猶予期間が過ぎた後、画像、レポート、ワークスペース情報を順次削除します。処理や外部サービスの状態により、完了まで15分以上かかります。

退会すると、セッションと他のワークスペースのメンバー権限も失効しますが、他の所有者のプロジェクトは削除しません。

GitHub IssueやStripeの請求書は削除しません。ワークスペースを削除すると、KUEからそのワークスペースの「支払い・解約を管理」を開けなくなります。そのため、必要な請求書は削除の前に取得しておきます。

画像キャッシュと当月の利用量記録については、次のデータ保持の説明を参照してください。

### レポートの処理状況

`getKueReportStatus(receipt, { apiBaseUrl }): Promise<KueReportStatus>` で、レポートの処理状況を取得できます。`receipt` には受付時の `id` と `receiptToken` が必要です。SDKは自動ではポーリングしません。

| `status` | 意味 |
| --- | --- |
| `received` | 受付済み |
| `queued` | 送信待ち（Issue作成の順番待ち） |
| `creating_issue` | Issue作成中 |
| `completed` | Issue作成済み。`githubIssue` にIssueの番号とURLが入る |
| `failed` | 失敗。`error.code` でエラーを確認 |

`receiptToken` は対象のレポートを読むための秘密情報です。ソースコード、公開Issue、ログへ記載しないでください。

## 利用上限とデータ保持

### プランと利用上限

| 項目 | Free | Indie |
| --- | --- | --- |
| 月額・ワークスペース単位 | US$0 | US$12（税込） |
| 送信できるプロジェクト | 1 | 無制限 |
| 月間送信数 | 100件 | 5,000件 |
| 画像保存容量 | 100 MB | 10 GB |
| 画像保存期間 | 受付から30日 | 受付から365日 |

送信数と保存容量はワークスペース全体で合算します。1 MBは1,000,000バイト、1 GBは1,000,000,000バイトです。月間枠は毎月1日0:00 UTC（日本時間9:00）にリセットされます。

基準価格は米ドル建てです。決済する最終金額と通貨はCheckoutで確認します。通貨換算には手数料が含まれる場合があり、カード会社などの手数料が別途かかることもあります。

月間枠または保存容量の上限に達すると、新規送信は受け付けません。超過分の自動課金はありません。

受付済みのレポートは、Issueの作成に失敗した場合も月間送信数に含まれます。再試行や削除をしても、利用数は戻りません。

Freeでも複数の接続情報を保存できます。ただし、送信できるのは選択した1つのプロジェクトだけで、他のプロジェクトは休止します。IndieからFreeへ戻った場合も同じ制限を適用します。

保存容量がFreeの上限を超えている間は、選択中のプロジェクトからも新規送信できません。

販売状況と契約条件は[料金ページ](https://kue.ischca.dev/pricing)で確認できます。

### Free送信先の切替制限

接続情報は複数保存できますが、Freeで新規送信できるのは選択した1つのリポジトリだけです。最初に接続したリポジトリを、初期の送信先として選択します。

別のリポジトリを接続するときは、現在の送信先と切替先を表示して確認を求めます。この確認で取り消した場合は、接続情報を保存しますが、送信先は変更せず、CLIの接続完了も保留します。

送信先を切り替えるだけであれば、既存キーの再発行や環境変数の手動更新は不要です。

新しい送信先で最初のFreeレポートを受け付けた時刻から24時間、別のリポジトリへの切替を制限します。制限の起点には端末のキャプチャ日時ではなく、サーバーの受付時刻を使用します。

接続、ビルド前の確認、失敗したアップロードでは、制限を開始しません。受付後にIssueの作成が失敗しても、受付件数と切替制限は維持します。

切替制限の期限はダッシュボードに表示します。

24時間が過ぎても、送信先を自動では切り替えません。ダッシュボードの「Freeで使うプロジェクトに選ぶ」を使うか、別のアプリを接続するときの確認で切り替えます。

旧プロジェクトからの新規送信は直ちに拒否し、切替後のリポジトリで最初に受け付けたFreeレポートから次の24時間を開始します。

同じリポジトリの継続利用、既存レポートの再試行、キーの再発行では、期限を延長しません。切替前に受け付けたレポートからは、引き続きIssueを作成できます。

切替制限は変わることのないGitHubリポジトリIDごとに適用します。改名、プロジェクトやワークスペースの削除と再作成、FreeとIndieの往復では、切替制限を解除しません。

Indieが有効な間は複数のプロジェクトから送信できます。Freeへ戻ると、保存済みの選択と、まだ終わっていない制限期間を再び適用します。選択していたプロジェクトが削除済みの場合は、その選択を別のプロジェクトへ自動では置き換えません。

月100件の枠と保存容量は全プロジェクトで共有し、切替ではリセットしません。この制限はGitHub所有者のワークスペース内のリポジトリを単位とし、同じリポジトリとキーを使うアプリや端末の数は制限しません。

有効なキーでも、選択していないプロジェクトでは `project_plan_paused` になります。制限期間中の切替操作は `free_project_locked` になります。これらは無効なキーや失効済みのキーの場合とは別の状態です。

接続先や支払い状態はGitHubにログインした後の管理画面だけに表示します。無効なプロジェクトキーから、他のプロジェクトの情報が分かることはありません。

ダッシュボードでは、Stripeとの同期で支払いの未完了を確認した場合、契約の終了を確認した場合、有効な有料期間を確認できない場合を区別して表示します。Freeへの変更自体は契約の解約ではありません。支払いの再試行が続く場合があります。

削除と再作成による切替制限の解除を防ぐため、ワークスペースの削除後も一部の情報を別途保持します。保持する情報はGitHub所有者のIDと種別から生成した秘密鍵付きハッシュ、制限対象のGitHubリポジトリID、既存の制限期限です。

この記録には氏名、リポジトリ名、プロジェクトキー、送信内容、Stripe IDを含めません。この記録は仮名化された情報であり、匿名化を保証しません。

制限期限が過ぎた後は判定に使用せず、定期処理で削除します。削除操作によって24時間の期限を延長することはありません。

### 保存期限と削除

画像の保存期間は受付時のプランで決まります。アップグレードしても、Freeのときに受け付けた画像の期限は延長しません。

Indieの契約が終了すると、Indieのときに受け付けた画像の期限は契約終了から最大30日後になります。この期限は元の365日の期限を超えません。期限はダッシュボードの各レポートで確認できます。

保存期限を過ぎると、元画像は順次削除され、画像リンクは期限終了の表示に置き換わります。元画像を含まない配信停止の案内画像は、再配信を防ぐために残る場合があります。

GitHub Issueの本文とメモは残ります。画像の期限が切れただけでは、KUEのレポート情報は削除されません。レポート情報は、プロジェクトまたはワークスペースを削除するときに削除の対象になります。

CDN、ブラウザ、GitHubのキャッシュにより、表示の更新に時間がかかる場合があります。即時の閲覧停止と、第三者が保存したコピーの削除は保証されません。期限切れ画像の復元には対応していません。

ワークスペースを削除して再作成しても、当月の枠はリセットされません。枠の不正な再取得を防ぐため、当月の使用件数と、同じGitHub所有者かどうかを照合するための仮名化された情報を保持します。

これらの情報は翌月以降の定期処理で削除します。この仮名化は匿名化を保証するものではありません。

### アクセス権と機密情報

- Cloudへの通信にはHTTPSを使用します。HTTPでのAPI、認証、画像へのアクセスは403で拒否します。通常ページへのGET/HEADリクエストのうち、クエリ文字列、Authorization、Cookieをいずれも含まないものだけを、308でHTTPSへリダイレクトします。リダイレクトや拒否は、すでにHTTPで送信した内容の漏えいを防ぐものではありません。
- 画像URLは、URLを知っている人が閲覧できるリンクです。非公開リポジトリの場合も含め、画像URLはGitHubのアクセス権とは連動しません。
- プロジェクトキーはアプリへ組み込める公開情報ですが、キーを取得した第三者も送信できます。濫用された場合はキーを再発行します。
- キーを再発行した後は、旧キーでの新規受付を拒否します。再発行の前に受け付けたレポートのIssue作成や画像URLは、キーを再発行しても取り消しません。
- 画像、メモ、`receiptToken` をログへ出力しないでください。送信前に秘密情報と個人情報を除外します。

## トラブルシューティング

### 症状と確認項目

| 症状 | 確認・対処 |
| --- | --- |
| ボタンが表示されない | `enabled`、`floatingButton`、ルートへの配置、画面端のハンドルを確認。リリースビルドではSDKがデフォルトで無効 |
| 端末保存後にIssueが作成されない | `cloud` より優先される `onSubmit` の指定、`cloud` の設定、送信待ちとレポートの処理状況を確認 |
| リポジトリが表示されない | GitHub個人アカウントまたは組織の所有者権限、対象リポジトリの管理権限、Appのリポジトリ権限、Issuesの有効化を確認して、一覧を再取得 |
| ワークスペースを操作できない | 選択中のワークスペース、KUEのワークスペースのメンバー権限、現在のGitHub所有者権限を確認。別の組織所有者には権限が自動で付与されない |
| 購入後もFreeのまま | 対象ワークスペースを確認して「契約状態を更新」を押す。重複して購入せず、解決しない場合はサポートへ連絡 |
| ワークスペースを削除できない | 契約の終了、開いたままのCheckoutの期限切れ、課金確認の完了を確認。契約期間の終わりに解約する予約をしただけでは削除できない |
| 退会できない | 所有するすべてのワークスペースの移管または削除が完了していることを確認 |
| CLIがルートを検出できない | アプリのパッケージ内で `--dry-run` を実行し、`--root` を指定。未対応の構造の場合は手動導入 |
| 接続承認リンクが期限切れ | セットアップが完了している場合はダッシュボードを利用。未完了の場合のみ、自分のターミナルで `init` を再実行。承認リンクは共有しない |
| 401・無効なプロジェクトキー | ダッシュボードに表示される現在の設定へ更新。旧キーの送信待ちは新キーへ自動で移行されない |
| 403・409・429による送信停止 | ワークスペースの月間枠、保存容量、選択中のプロジェクトを確認。短時間のレート制限の場合は、時間をおいて再試行 |
| 画像を表示できない | 保存期限と削除状態を確認。連続した閲覧で制限された場合は、時間をおく。期限切れ画像は復元できない |
| キャプチャ・追加トリガーが動作しない | 対応OS、依存関係、development buildの再ビルドを確認。Simulatorではボタンからの起動でも検証 |
