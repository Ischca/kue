# KUE ドキュメント

KUEは、Expo / React Nativeアプリに画面キャプチャ・範囲選択・メモ入力を組み込むSDKです。送信先には、GitHub Issueを作成するKUE Cloud、またはアプリ側の保存処理を指定します。

対象バージョン: SDK・CLI **0.3.4**。本書はインストール手順、公開API、Cloudの利用条件を記載しています。

## 動作要件

| 項目 | 対応範囲 |
| --- | --- |
| アプリ | Expo SDK 54〜57 / React Native |
| OS | iOS・Android。Webの画面キャプチャは非対応 |
| CLI | Node.js 22.13以上 |
| ライセンス | SDK・CLI: MIT。Cloud: 別途提供するホステッドサービス |

Cloud連携には、GitHubアカウントと、送信先リポジトリへのKUE QA GitHub Appのインストールが必要です。接続するユーザーは、個人リポジトリの所有者、または組織の所有者で、対象リポジトリの管理権限も持つ必要があります。Appをインストールできない場合の連絡先は[サポート](mailto:kue@ischca.dev)です。

`onSubmit` による独自保存はCloudアカウントなしで利用できます。通常のSDK導入・更新にyalcは不要です。

## CLIによるセットアップ

### 実行手順

アプリの変更を保存し、Expoアプリのパッケージ、またはワークスペースのルートで実行します。

```sh
npx kue-qa init
```

現在のパッケージに `expo` の依存関係があれば、そのパッケージを使用します。それ以外は `pnpm-workspace.yaml` の `packages`、または `package.json` の `workspaces` からExpoアプリを検出します。両方ある場合はpnpmの定義を優先します。候補が1つなら自動選択し、複数なら候補を表示して変更せず終了します。対象を選ぶ場合は次のように指定します。

```sh
npx kue-qa init --app apps/mobile
```

自動探索は実行ディレクトリ内に限定します。隠しディレクトリ、シンボリックリンク、`node_modules`・`vendor`・`build`・`dist`・`coverage`・`ios`・`android` は探索しません。2,000ディレクトリを超える場合やワークスペース定義がない場合は、`--app` を指定するかアプリ内で実行します。`--app` は実行ディレクトリ内のリンクでないディレクトリを指定します。

1. CLIがルートコンポーネントとGitHubリポジトリを検出します。
2. 初回または明示的な再接続時は、ブラウザでGitHubへログインし、送信先を確認して「接続」を押します。必要な場合のみ、GitHubで対象リポジトリへのアクセスを許可します。
3. CLIがSDK・依存関係をインストールし、ルートコンポーネントへKUEを追加します。
4. 変更差分を確認してExpoを起動します。ネイティブ依存関係を追加した場合はdevelopment buildを再ビルドします。
5. レポートを送信し、[ダッシュボード](https://kue.ischca.dev/app)の配送状態とIssueを確認します。

接続承認リンクの有効期限は15分です。自分で開始したセットアップのみを承認してください。`init` の実行だけではIssueは作成されません。

接続完了後はURLが通常のダッシュボード（`/app`）に切り替わります。期限切れの接続リンクを開いた場合も、ログイン後はダッシュボードを表示します。セットアップ済みのプロジェクトを再接続する必要はありません。CLIのセットアップが未完了の場合のみ、`init` を再実行します。

接続先リポジトリのGitHub所有者からワークスペースが決まります。初回接続者がKUEのワークスペース所有者になります。既存ワークスペースがある場合、別のGitHub組織所有者にもKUEの管理権限が自動付与されるわけではありません。

接続画面はCLIが指定したリポジトリを固定表示します。「接続」を押すと、許可済みならそのまま接続します。未許可なら同じタブでGitHubへ移動します。個人アカウントまたは組織を選び、「Only select repositories」で対象リポジトリだけを許可できます。GitHubからKUEへ戻ると、最初に指定した送信先の権限を再確認し、接続を完了します。接続ボタンをもう一度押す必要はありません。

GitHubで許可を保存した後、自動でKUEへ戻らない場合はブラウザの「戻る」で元の接続画面へ戻ります。この場合も、戻った時点で接続を再開します。

接続開始の操作は本人のブラウザ・ログインアカウント・送信先に紐づけ、有効期限内に一度だけ再開します。GitHubでキャンセルした場合、別のリポジトリを許可した場合、組織の承認待ちの場合は接続しません。承認後は「再読み込み」で確認し、「接続」を押します。未完了のセットアップが期限切れの場合はCLIの `init` から再開します。GitHubでの許可操作は省略できません。

### initの冪等性

以下はCLI 0.3.4以降の動作です。0.3.3以前は再実行時にも接続承認・依存インストール・設定ファイルの書き込みを行います。

管理対象の接続設定・組み込み・インストール済み依存が同じなら、通常の `init` はブラウザ承認、ネットワーク通信、パッケージマネージャー実行、ファイル書き込みを行わず終了します。ファイルの更新日時とlockfileも維持します。既存の0.3.3形式の設定を読み取れます。これはローカル状態の確認であり、Cloudの接続やキーの有効性を再検証するものではありません。

| 状態・指定 | 動作 |
| --- | --- |
| SDK更新 | CLIと同じSDKバージョンへ更新。接続設定と互換性のある既存のネイティブ依存は維持。新しいSDKを古いCLIでダウングレードしない |
| 不足している依存 | 宣言されていないSDK・必須ネイティブ依存だけを追加。ネイティブ依存の指定範囲はインストール済みExpoの情報を使用 |
| 依存の不整合 | 宣言済みだが未インストール、またはバージョンが不整合なら停止。先にlockfileから依存を復元するか、依存の明示的な更新を行う |
| `--reconnect` | 明示的にブラウザ承認を行い、設定を再取得。送信先変更には `--repository OWNER/REPO`、サーバー変更には `--server URL` を併用 |
| `--config project.json` | 明示指定した設定だけを適用。同じ設定なら書き直さない。`--reconnect`・`--repository`・`--server` と併用不可 |
| `--skip-install` | 依存の確認・追加を行わない。依存を適切に導入したことを意味しない |
| `--sdk sdk.tgz` | ローカルtarballの内容ハッシュとインストール状態を比較。同じ入力なら再インストールしない。継続使用時も同じオプションを指定 |
| 管理対象ファイルの不整合 | JavaScript設定を実行せず、壊れた設定や組み込み、カスタマイズされた型宣言を勝手に初期化せず停止 |

ブラウザ承認後は `.kue/setup.json` に接続先と設定のハッシュ、ローカルtarball使用時は内容ハッシュとSDKバージョンを保存します。認証トークンや絶対パスは保存しません。このメタ情報はコミットできます。旧設定などで接続先の記録がない場合、`--repository` の指定には明示的な `--reconnect` が必要です。通常の再実行ではGit remoteの変更から接続先を自動変更しません。

必要なインストールを実行する場合、パッケージマネージャーが関連するlockfileを更新することがあります。差分を確認してください。明示的な `--reconnect` は毎回承認を要求します。

### オプション

| オプション | 動作 |
| --- | --- |
| `--dry-run` | 検出結果を表示。ネットワーク通信・ファイル変更なし |
| `--app apps/mobile` | 対象のExpoパッケージを指定。相対パスはコマンドの実行場所が基準 |
| `--repository OWNER/REPO` | 接続先のGitHubリポジトリを指定 |
| `--reconnect` | 明示的に接続設定を再取得。既存の送信先・サーバーを変更する場合も必要 |
| `--root app/_layout.tsx` | 組み込み先のルートファイルを指定 |
| `--no-open` | ブラウザを起動せず、接続承認リンクを表示 |
| `--config project.json` | ダッシュボードの公開設定JSONを使用。ブラウザでの接続承認を省略 |
| `--skip-install` | 依存関係のインストールを省略。必要なパッケージは別途追加 |
| `--server https://YOUR-KUE-HOST` | Cloudの接続先を変更。既定は `https://kue.ischca.dev` |
| `--sdk /path/to/sdk.tgz` | ローカル検証用のSDK tarballを指定 |

`--root` の相対パスは選択されたアプリ、`--config` と `--sdk` の相対パスはコマンドの実行場所が基準です。依存関係と `.kue` は選択されたアプリ内に追加します。パッケージマネージャーはアプリから親ディレクトリへ、`packageManager` とlockfileで判定します。

`--config` 指定時はJSON内の接続先を使用します。CLIの自動編集に対応しないルート構造では、手動でSDKを組み込みます。

### 生成ファイル

| ファイル | 内容・管理方法 |
| --- | --- |
| `.kue/config.js` / `.kue/config.d.ts` | 公開投稿専用キーを含む接続設定と型定義。バージョン管理へ追加可能 |
| `.kue/backup-*.txt` | 変更前のアプリソース。ローカルで保管し、コミット対象から除外 |

GitHubユーザートークンや課金用の認証情報をアプリへ保存する処理はありません。

## SDKの手動導入

### パッケージの追加

以下はnpmの例です。既存アプリと同じパッケージマネージャーを使用し、lockfileを統一します。

```sh
npm install @kue-qa/react-native@0.3.4
npx expo install expo-application expo-constants expo-device expo-file-system expo-image-manipulator react-native-view-shot react-native-safe-area-context
```

### Cloud接続と配置

ダッシュボードで取得した公開設定を `.env.local` へ設定します。キーの例は対象プロジェクトの投稿専用キーに置き換えます。GitHubトークン・秘密鍵は指定しません。

```dotenv
EXPO_PUBLIC_KUE_API_BASE_URL=https://kue.ischca.dev
EXPO_PUBLIC_KUE_PROJECT_KEY=pk_REPLACE_WITH_PROJECT_KEY
```

ルートに `Kue` を1つ配置します。次の例はExpo Routerの `app/_layout.tsx` です。

```tsx
import { Stack } from 'expo-router';
import { Kue } from '@kue-qa/react-native';

export default function RootLayout() {
  return (
    <>
      <Stack />
      <Kue cloud={{
        apiBaseUrl: process.env.EXPO_PUBLIC_KUE_API_BASE_URL!,
        projectKey: process.env.EXPO_PUBLIC_KUE_PROJECT_KEY!,
      }} />
    </>
  );
}
```

`Slot` を使用する構成では `Stack` を置き換えます。Expo Router以外ではアプリのルートコンポーネントに配置します。環境変数の読み取りはアプリ側の処理であり、SDKによる自動読み取りはありません。

### 独自の保存処理

`onSubmit` は `KueLocalReport` を受け取り、`void` または `Promise<void>` を返します。次の `saveReportAndCopyImage` はアプリ側で実装する保存関数です。

```tsx
<Kue onSubmit={async (report) => {
  await saveReportAndCopyImage(report);
}} />
```

`onSubmit` と `cloud` の同時指定時は `onSubmit` が優先され、Cloud送信とオフラインキューは使用されません。どちらも未指定の場合、レポートは自動保存されません。

画像URIは一時ファイルを参照します。コールバック完了後も画像が必要な場合は、Promiseの完了前にコピーまたはアップロードします。

| `KueLocalReport` のフィールド | 内容 |
| --- | --- |
| `clientReportId` | 同じ送信内容の再試行で維持する識別子 |
| `memo` | 入力されたメモ |
| `crop` | 正規化された範囲座標 `x`・`y`・`width`・`height` |
| `screenshot` | 切り取り後の画像URI・幅・高さ・MIMEタイプ |
| `sourceSize` | 元画像の幅・高さ |
| `context` | 端末・アプリのメタ情報 |
| `capturedAt` | キャプチャ日時 |

## キャプチャとIssue作成

### 操作手順

1. KUEボタンをタップしてキャプチャを開始します。
2. 対象範囲を選択し、メモを入力します。
3. 秘密情報・個人情報が含まれていないことを確認し、Sendを選択します。
4. Cloud連携時はダッシュボードから配送状態と作成されたIssueを確認します。

### フローティングボタン

既定は「KUE」の文字ボタンです。キャラクターを表示するには `buttonDesign="mascot"` を指定します。どちらも操作方法とタッチ領域は同じです。画像はSDKに同梱され、追加のダウンロードやネイティブ依存関係は不要です。

```tsx
<Kue cloud={cloud} buttonDesign="mascot" />
```

| 操作 | 結果 |
| --- | --- |
| タップ | キャプチャを開始 |
| ドラッグ | 位置を移動。キャプチャは開始しない |
| 画面端で離す | ボタンを小さなハンドルへ収納 |
| ハンドルをタップ | ボタンを再表示 |
| 長押しして離す | オフラインキュー有効時に送信待ち一覧を表示 |

位置はアプリ再起動後に引き継がれません。

### Issueの内容

Issueには切り取った画像、メモ、端末・アプリのメタ情報が含まれます。既定ラベルは `kue` です。ラベルが存在しない場合は作成し、既存ラベルの設定は変更しません。ラベル名のカスタマイズは非対応です。

## SDK設定リファレンス

### KueProps

すべてのPropsは省略可能です。送信・保存には `cloud` または `onSubmit` の指定が必要です。

| Prop | 既定値 | 動作 |
| --- | --- | --- |
| `enabled` | `__DEV__` | SDKの有効・無効。リリースビルドでは既定で無効 |
| `cloud` | 未指定 | `KueCloudConfig` でCloud送信を設定 |
| `onSubmit` | 未指定 | 独自保存コールバック。`cloud` より優先 |
| `context` | `{}` | 自動取得したメタ情報を補完・上書き |
| `floatingButton` | `true` | ボタンの表示。`false` でも他の起動方法は使用可能 |
| `buttonDesign` | `"classic"` | `"classic"` は文字ボタン、`"mascot"` はキャラクターボタン |
| `triggers` | 未指定 | 追加の起動処理を登録する配列 |
| `offlineQueue` | `false` | Cloud送信待ちの端末保存を有効化 |
| `onQueued` | 未指定 | 端末保存後、Cloud未受付の場合に `clientReportId` を通知 |
| `onReceipt` | 未指定 | Cloud受付後に `KueReceipt` を通知 |
| `onError` | 未指定 | 撮影・送信エラーを通知。未指定時はアラート表示 |
| `capture` | SDK標準の撮影処理 | `KueCaptureAdapter` で撮影処理を置換。テスト・独自実装向け |

社内QA用リリースビルドで有効化する場合は、アプリ側の明示的な条件で `enabled` を設定します。一般配布ビルドでの無条件有効化は避けてください。

### KueCloudConfig

| プロパティ | 必須・既定値 | 内容 |
| --- | --- | --- |
| `apiBaseUrl` | 必須 | CloudのベースURL。`/v1/reports` を含めない |
| `projectKey` | 必須 | `pk_...` 形式の公開投稿専用キー |
| `timeoutMs` | 既定 `15000` | HTTPリクエストのタイムアウト（ミリ秒） |

### メタ情報

OS、端末モデル、アプリバージョン・ビルド番号、画面サイズを自動取得します。取得可能な場合はExpo Updatesの情報も含みます。端末ID・個人の端末名・画面のルートは自動取得しません。

アプリ固有の情報は `context` に指定します。次はExpo Routerのルートテンプレートを渡す例です。

```tsx
import { useSegments } from 'expo-router';
import { Kue, type KueCloudConfig } from '@kue-qa/react-native';

export function QaReporter({ cloud }: { cloud: KueCloudConfig }) {
  const segments = useSegments();
  return <Kue cloud={cloud} context={{ route: `/${segments.join('/')}` }} />;
}
```

この例を使用する場合は、別の `Kue` を重複して配置しません。メタ情報の優先順位は、自動取得値 → `context` → `reportIssue({ context })` の順です。URLクエリやユーザーIDではなく、匿名化したルートテンプレートを指定します。

## 起動APIとトリガー

### reportIssue

`reportIssue(options?): Promise<void>` は、マウント済みで有効なKUEの入力画面を開きます。`options.memo` は初期メモ、`options.context` はレポート単位のメタ情報です。

```ts
import { reportIssue } from '@kue-qa/react-native';
await reportIssue({ memo: 'Describe the issue' });
```

有効なKUEが存在しない場合は `KueUnavailableError` になります。このAPIは送信を実行せず、戻り値に受付情報は含みません。

### シェイク・スクリーンショット

追加のトリガーは任意です。使用するモジュールを追加し、development buildを再ビルドします。

```sh
npx expo install expo-sensors expo-screen-capture
```

```tsx
import { shakeTrigger } from '@kue-qa/react-native/shake';
import { screenshotTrigger } from '@kue-qa/react-native/screenshot';

const triggers = [shakeTrigger, screenshotTrigger];
<Kue cloud={cloud} triggers={triggers} />
```

`cloud` は設定済みの `KueCloudConfig` です。配列はコンポーネント外などに定義し、参照を安定させます。`floatingButton={false}` でボタンのみ非表示にできます。

| トリガー | 依存モジュール | 対応・動作 |
| --- | --- | --- |
| `shakeTrigger` | `expo-sensors` | シェイクを検知して入力画面を開く |
| `screenshotTrigger` | `expo-screen-capture` | iOS・Android 14以降。OSのスクリーンショットを検知し、現在のアプリ画面を再撮影 |

トリガーはKUEが有効・前面・待機中の場合に購読されます。写真ライブラリの読み取りや自動送信は行いません。

### Android権限

KUEは追加の権限要求やアプリ共有のセンサー間隔変更を行いません。オプションのExpoモジュールが追加する `ACTIVITY_RECOGNITION`・`READ_EXTERNAL_STORAGE`・`READ_MEDIA_IMAGES` は、アプリの他機能で不要な場合に限り `android.blockedPermissions` で除外できます。Android 14以降のスクリーンショット検知に必要な `DETECT_SCREEN_CAPTURE` は維持します。

## オフラインキュー

### 有効化

`offlineQueue` はCloud送信専用の永続キューです。既定では無効です。`onSubmit` による独自保存は対象外です。

```tsx
<Kue cloud={cloud} offlineQueue />
```

送信前にアプリ内の `Documents/kue-outbox-v1` へ保存します。追加のネイティブ依存・権限・アプリ側DB設定は不要です。

### 保存上限と再試行

| 項目 | 値・動作 |
| --- | --- |
| 件数 | 全送信先を合計して10件 |
| 合計容量 | 50 MiB |
| 画像1枚 | 10 MiB以下 |
| 保存期限 | 7日。期限を過ぎた項目は次のキューアクセス時に削除 |
| 自動再試行 | アプリが前面の間に実行。終了中・バックグラウンドでの実行保証なし |
| 通信エラー | 待機後に再試行 |
| 無効なキー・利用上限 | 自動再試行を停止し、手動操作を待機 |

接続先やキーを変更しても、既存の項目は新しい送信先へ自動転送されません。端末保存のみでCloudが未受付の場合は `onQueued`、Cloud受付後は `onReceipt` が通知されます。

### 管理API

以下の関数は `@kue-qa/react-native` からインポートします。`cloud` は対象の接続設定、`id` は一覧の `clientReportId` です。

| API | 結果 |
| --- | --- |
| `pendingKueReports(cloud)` | 送信待ちの識別子・保存日時・状態を取得 |
| `retryPendingKueReports(cloud, { force: true })` | 手動で再試行。戻り値は `Promise<void>` |
| `discardPendingKueReport(cloud, id)` | 端末内の対象項目を破棄 |

SDK独自の暗号化はなく、バックアップはホストアプリの方針に従います。端末側で破棄しても、Cloud受付済みのデータは取り消されません。

## ワークスペース管理と送信状態

### ワークスペースと権限

ワークスペースは、1つのGitHub個人アカウントまたは組織に対応する、契約・プロジェクト・利用量の単位です。別のGitHub所有者のリポジトリは別ワークスペースになります。リポジトリの改名では所属は変わりません。別の所有者へのGitHub上の移管は、KUEの所属を自動変更しません。

管理操作には、自分のGitHubアカウントでのログイン、KUEの所属権限、現在のGitHub所有者権限が必要です。投稿専用キーは管理権限を付与しません。テスターや端末の数による追加料金はありませんが、別所有者・別顧客の業務を1契約にまとめることはできません。メンバー招待には対応していません。

### ダッシュボード

初回の[ダッシュボード](https://kue.ischca.dev/app)にはリポジトリ接続画面を表示し、空のワークスペース選択欄は表示しません。リポジトリ一覧は自動取得します。対象がなければ「接続」からGitHubで許可します。CLIを経由せずダッシュボードを開いた場合は送信先が未指定のため、戻った後にリポジトリを選び「接続」を押します。一覧にないリポジトリを追加する場合は「GitHubのアクセス権を設定」を使用します。接続時にワークスペースが自動作成されます。

接続後は対象ワークスペースを選択し、接続設定、プラン、当月の送信数、画像容量、直近20件のレポートを確認します。課金・ワークスペース削除・所有者移管はKUEのワークスペース所有者のみ実行できます。

| 操作 | 影響 |
| --- | --- |
| 公開設定の取得 | 接続済みプロジェクトのSDK設定を再表示 |
| 投稿キーの更新 | 旧キーを失効。利用中の全アプリに新しい設定が必要。既存Issueは維持 |
| 配送の再試行 | 失敗したレポートを再処理。作成結果が不明な場合は既存Issueを再確認 |
| Freeの有効プロジェクト選択 | 送信可能な1プロジェクトを指定。休止は削除とは別の状態 |
| プロジェクトの削除 | 投稿を停止し、画像・レポートを順次削除。GitHub Issueは削除しない |

### 購入・解約

1. ダッシュボードで対象ワークスペースを確認し、[料金ページ](https://kue.ischca.dev/pricing)と[利用規約](https://kue.ischca.dev/terms)で利用枠・保存期間・解約・返金条件を確認します。Indieの購入操作からStripe Checkoutを開き、最終金額・決済通貨・月額の自動更新を確認して、規約への同意後に購入します。
2. ダッシュボードでIndieへの切替と契約期限を確認します。反映が遅れる場合は課金状態を再同期します。購入画面へ戻ったことだけでは契約反映の確認になりません。
3. 支払方法・請求書・解約は支払い管理のStripe Customer Portalから操作します。次回更新前に解約すると、支払い済みの契約期間末にFreeへ戻ります。

毎月自動更新です。請求周期と月間送信枠の更新日は別です。支払いに失敗して有効な契約を確認できない場合はFreeの制限が適用されます。支払方法の修正後、課金状態を再同期します。プロジェクトの削除やSDKのアンインストールでは契約は解約されません。

決済にはStripe Managed Paymentsを利用します。Checkoutで現地通貨が表示・決済される場合があり、領収書・請求書はLinkから届きます。KUEの支払い管理に加えてLinkでも注文・契約・支払方法を管理できます。返金には購入時に提示されるLinkの条件が優先する場合があり、法令上の権利を制限しません。Linkへのデータ削除請求では契約が終了する場合があります。KUEの画像・レポートの削除は別途KUEで操作します。

### 所有者の移管

自動移管は、Stripeの課金アカウントがまだ作成されていないFreeの組織ワークスペースに限ります。個人ワークスペース、またはCheckoutを開始して課金アカウントが作成されたワークスペースは対象外です。対象外の契約変更はサポートへ連絡してください。

1. 移管先のユーザーが、自分のGitHubアカウントでKUEへログインします。承認時にGitHub組織の所有者権限が必要です。
2. 現在のKUE所有者がダッシュボードで移管先のGitHubユーザー名と、確認用の組織名を入力して申請します。
3. 移管先が自分のダッシュボードで組織名を確認し、24時間以内に承認します。申請者は取消、受信者は辞退できます。

申請中は購入を開始できません。完了すると元所有者のKUE管理権限を除去しますが、プロジェクト・送信キー・利用数は維持します。必要に応じて新所有者が投稿キーを更新してください。GitHub上の組織所有者そのものを変更する操作ではありません。

### ワークスペースの削除・退会

1. 契約がある場合は先に解約し、契約終了を待ちます。未完了のCheckoutや課金確認中の状態では削除できません。
2. 対象ワークスペースの削除操作で、GitHub所有者名を入力して確認します。全プロジェクトの投稿とKUE経由の画像アクセスを停止します。
3. 全所有ワークスペースの削除完了、または移管後に、折りたたまれた「アカウント削除」を開き、自分のGitHubユーザー名を入力して退会します。

処理中の送信に対する15分の猶予後、画像・レポート・ワークスペース情報を順次削除します。処理や外部サービスの状態により、完了まで15分以上かかります。退会するとセッションと他ワークスペースの所属権限も失効しますが、他所有者のプロジェクトは削除しません。

GitHub IssueやStripeの請求書は削除しません。ワークスペース削除後はKUEからその支払い管理を開けなくなるため、必要な請求書は事前に取得します。画像キャッシュと当月の利用量記録については、次のデータ保持の説明を参照してください。

### 配送状態

`getKueReportStatus(receipt, { apiBaseUrl }): Promise<KueReportStatus>` で状態を取得できます。`receipt` には受付時の `id` と `receiptToken` が必要です。SDKは自動ポーリングしません。

| `status` | 意味 |
| --- | --- |
| `received` | 受付済み |
| `queued` | 配送キューで待機中 |
| `creating_issue` | Issue作成処理中 |
| `completed` | Issue作成完了。`githubIssue` に番号とURLを格納 |
| `failed` | 配送失敗。`error.code` でエラーを確認 |

`receiptToken` は対象レポートを読むための秘密情報です。ソースコード・公開Issue・ログへ記載しないでください。

## 利用上限とデータ保持

### プランと利用上限

| 項目 | Free | Indie |
| --- | --- | --- |
| 月額・ワークスペース単位 | US$0 | US$12（税込） |
| 送信可能なプロジェクト | 1 | 無制限 |
| 月間送信数 | 100件 | 5,000件 |
| 画像保存容量 | 100 MB | 10 GB |
| 画像保存期間 | 受付から30日 | 受付から365日 |

送信数・保存容量はワークスペース全体で合算します。1 MBは1,000,000バイト、1 GBは1,000,000,000バイトです。月間枠は毎月1日0:00 UTC（日本時間9:00）に更新します。基準価格は米ドル建てです。決済する最終金額・通貨はCheckoutで確認します。通貨換算には手数料が含まれる場合があり、カード会社などの手数料が別途かかることもあります。

月間枠または保存容量に達すると、新規送信は受け付けません。超過分の自動課金はありません。受付済みレポートは配送失敗時も月間送信数に含まれ、再試行・削除で利用数は戻りません。

Freeでは1プロジェクトを接続できます。IndieからFreeへ戻って複数のプロジェクトが残る場合、選択した1プロジェクトのみ送信可能になり、他は休止します。保存容量がFreeの上限を超えている間は、有効プロジェクトも新規送信できません。販売状況と契約条件は[料金ページ](https://kue.ischca.dev/pricing)で確認できます。

### 保存期限と削除

画像の保存期間は受付時のプランで決まり、アップグレードしても受付済みのFree画像の期限は延長しません。Indieの契約終了後、Indie画像は契約終了から最大30日で期限となり、元の365日の期限を超えません。期限はダッシュボードの各レポートで確認できます。

保存期限後、元画像は順次削除され、画像リンクは期限終了の表示に置き換わります。元画像を含まない配信停止の案内画像は、再配信防止のため残る場合があります。GitHub Issueの本文・メモは残ります。画像の期限切れだけではKUEのレポート情報は削除されず、プロジェクトまたはワークスペースの削除対象になります。

CDN・ブラウザ・GitHubのキャッシュにより表示の更新に時間がかかる場合があります。即時の閲覧停止と、第三者が保存したコピーの削除は保証されません。期限切れ画像の復元には対応していません。

ワークスペースを削除・再作成しても当月枠はリセットされません。不正な再取得を防ぐため、当月の使用件数と、同じGitHub所有者を照合するための仮名化された情報を保持し、翌月以降の定期処理で削除します。これは匿名化を保証するものではありません。

### アクセス権と機密情報

- 画像URLは、URLを知っている人が閲覧できるリンクです。非公開リポジトリを含め、GitHubのアクセス権とは連動しません。
- 投稿専用キーはアプリへ組み込める公開情報ですが、取得した第三者による投稿も可能です。濫用時はキーを更新します。
- 画像・メモ・受付トークンをログへ出力しないでください。送信前に秘密情報・個人情報を除外します。

関連文書: [利用規約](https://kue.ischca.dev/terms) / [プライバシーポリシー](https://kue.ischca.dev/privacy)。

## 更新とアンインストール

### SDKの更新

現在の正式版を指定して更新します。別バージョンを使用する場合は、公開済みバージョンと変更履歴を確認して番号を置き換えます。

```sh
npm install @kue-qa/react-native@0.3.4
```

CLIでSDKを更新する場合は、対象バージョンを指定します。既存の接続設定は再利用します。設定を再取得する場合だけ `--reconnect` を追加します。

```sh
npx kue-qa@0.3.4 init
```

CLIは自身と同じバージョンのSDKを使用します。0.3.4以降のCLIは、新しいSDKの暗黙のダウングレードを拒否します。変更がなければ `init` は何も書き換えません。更新時は差分を確認してください。実行していない間の自動SDK更新は行いません。

依存関係やネイティブモジュールを変更した場合はdevelopment buildを再ビルドし、実機で撮影・送信を検証します。依存バージョンはアプリのlockfileで管理します。

### アンインストール

1. 端末内の送信待ちレポートを送信または破棄します。
2. `Kue`、独自の起動処理、接続設定をアプリから除去します。
3. SDKをアンインストールします。Expoの共有依存は他機能での使用有無を確認してから削除します。

SDKのアンインストールでは、CloudプロジェクトやGitHub Issueは削除されません。

## トラブルシューティング

### 症状と確認項目

| 症状 | 確認・対処 |
| --- | --- |
| ボタンが表示されない | `enabled`、`floatingButton`、ルートへの配置、画面端のハンドルを確認。リリースビルドでは既定で無効 |
| 端末保存後にIssueが作成されない | `onSubmit` の優先、`cloud` 設定、送信待ちと配送状態を確認 |
| リポジトリが表示されない | GitHub個人・組織の所有者権限、対象リポジトリの管理権限、Appのリポジトリ権限、Issuesの有効化を確認して一覧を再取得 |
| ワークスペースを操作できない | 選択先、KUEの所属権限、現在のGitHub所有者権限を確認。別の組織所有者への自動権限付与は行わない |
| 購入後もFreeのまま | 対象ワークスペースを確認して課金状態を再同期。重複購入せず、未解決ならサポートへ連絡 |
| ワークスペースを削除できない | 契約の終了、開いたCheckoutの失効、課金確認の完了を確認。期間末解約の予約だけでは削除不可 |
| 退会できない | 所有ワークスペースの移管または物理削除完了を確認 |
| CLIがルートを検出できない | アプリのパッケージ内で `--dry-run` を実行し、`--root` を指定。未対応の構造は手動導入 |
| 接続承認リンクが期限切れ | セットアップ済みならダッシュボードを利用。未完了の場合のみ、自分のターミナルで `init` を再実行。承認リンクは共有しない |
| 401・無効な投稿キー | ダッシュボードの現行設定へ更新。旧キーの送信待ちは新キーへ自動移行されない |
| 403・409・429による送信停止 | ワークスペースの月間枠・保存容量・有効プロジェクトを確認。短時間のレート制限は待機して再試行 |
| 画像を表示できない | 保存期限・削除状態を確認。連続閲覧制限の場合は待機。期限切れ画像は復元不可 |
| 撮影・追加トリガーが動作しない | 対応OS・依存関係・development buildの再ビルドを確認。Simulatorではボタンからの起動でも検証 |

### SDKエラー

Cloud通信エラーは `KueCloudError.code` で分類します。HTTP応答がある場合は `status`、サーバーのエラーコードがある場合は `serverCode` も取得できます。

| `code` | 分類 |
| --- | --- |
| `invalid_config` | 接続設定が不正 |
| `invalid_report` | 送信データが不正 |
| `network_error` | ネットワーク通信の失敗 |
| `request_timeout` | リクエストのタイムアウト |
| `unexpected_response` | 応答形式が想定外 |
| `upload_rejected` | サーバーがリクエストを拒否 |
